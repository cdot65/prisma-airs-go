### Findings

**Required (process, carried over and still open):** the handoff must name the **new commit created from this staged tree**. `bd6a0f4` contains none of this work, and the delta is still uncommitted. Per the brief, tagging/publication stay unauthorized and the future version stays pending — the guide's and release notes' "v0.8.1 does not contain this work" language is still accurate and invents no tag.

**Optional, highest value first:**

1. **The recipe's *other* explicit-override direction is still unlinked and untested — and this one is silent.** `consumerState:95-97` transfers presence for **every** name from `FieldNames()`, including `JSONOmitted`, and `SetFieldPresence` sets `explicit=true` (`profile_json.go:42-56`). After a rebuild, assigning a real value to a field that was omitted in the source — the ordinary "apply new Terraform config on top of prior state" step — is **silently dropped**: `inferredProfilePresence:136-148` returns the stored `JSONOmitted` and the `JSONPresent`-nil escape hatch doesn't apply. Round 1's item 1 covered the loud half (nil + explicit present → marshal error); this half loses data quietly. The general rule *is* stated at guide `:101-102` ("`JSONOmitted` suppresses a field even when it has a nonzero value"), so it's derivable, but the rebuild block at `:191-196` mentions `ResetFieldPresence` only in a removal context. Closing it is one sentence ("after a rebuild, assigning a value to a field that was omitted in the source requires `SetFieldPresence(name, JSONPresent)` or `ResetFieldPresence(name)`") plus a four-line case in `TestTerraformProfileConsumerRebuiltRemoval`.
2. **`FieldNames()` content is never asserted against the models' json tags.** The AST test checks the method *exists*; the reachable-model test checks the *signature* via interface satisfaction; only `DataLeakMember` has its exact list pinned (`:446`). Wrong-alias wrappers can't compile, so the realistic residual is an exported field that gains no `json` tag — it would vanish from both `FieldNames()` and the wire with nothing flagging it, while the godoc promises "all known typed wire names." `TestProfileJSONReachableModelCoverage:97-118` already has the type in hand: comparing `FieldNames()` to the sorted tag names derived by reflection (and erroring on an exported, non-`-` field with an empty tag) would cover all 25 models for ~8 lines.
3. **Marker coupling is by literal string.** The child's `t.Logf` text (`:440`) and the parent's `bytes.Contains` (`:75`) are independent literals; renaming one silently weakens the guard back to round-1 behavior. A shared package-level const fixes it. The positional `--` scan (`:388-392`) is unchanged and still fine.
4. **Guide wording nit:** "Added DLP members, topic references, toxicity categories, source-code settings, and their extensions exercise branches absent from the original fixture" (`:246-247`) reads as though `testdata/directional-security-profile.json` grew these; it is unchanged, and the augmentations live in the parent test before the bytes hit disk. One clause ("the suite constructs them in-test") removes the ambiguity.
5. **No deep-copy/bulk-presence helper, by design.** Providers must reimplement ~130 lines of `consumerState`/`consumerRebuild` plumbing. Ownership is explicitly Terraform's responsibility and the guide points at a JSON round-trip for independent copies, so this is correct scoping — but a one-line statement in the rebuild block that the SDK deliberately ships no deep-copy helper would set expectations.
